## 4. System Architecture

To guarantee modularity, separation of concerns, and robust data handling within the F' framework, **every single element of this project will strictly adhere to an Application / Manager / Driver architecture.**

### The Three-Tiered Paradigm

This architecture will be applied universally across the system's F' topology:

1. **Driver Layer:** Handles low-level hardware interfacing, protocols, and raw I/O.
2. **Manager Layer:** Handles intermediate processing, state management, calibration, and data formatting.
3. **Application Layer:** Handles high-level orchestration, business logic, and telemetry streaming.

### Component Implementation: Wii Balance Board

Following the mandated architecture, the Wii Balance Board integration will be split into three distinct, interconnected components:

* **Wii Board Driver:**
* Manages the physical Bluetooth/USB connection to the Wii board.
* Polls or receives raw sensor data (byte streams).
* Outputs raw sensor readings to the Manager layer without applying logic.


* **Wii Board Manager:**
* Receives raw I/O from the Driver.
* Applies calibration offsets (tare weight).
* Filters sensor noise and converts raw bytes into standardized weight metrics (e.g., kilograms or pounds).


* **Wii Board Application:**
* Consumes the processed weight data from the Manager.
* Determines sampling and reporting rates.
* Handles high-level business logic (e.g., triggering alerts if the hive weight drops rapidly).
* Packages and dispatches the final telemetry packets to the F' communications layer for streaming to the server.
